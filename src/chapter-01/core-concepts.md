# 1.2 MCP 的核心概念

## MCP 是什么

Model Context Protocol（MCP）是一种**让 AI 模型调用外部工具和服务**的标准化协议。它的设计目标是：

> 一次实现，任何 AI Client 都能用。

## 核心组件

```
┌─────────────────────────────────────────────────────┐
│                   AI Client                         │
│            (Codex / Cursor / Claude Code)           │
└──────────────────────┬──────────────────────────────┘
                      │ MCP 协议（JSON-RPC）
                      ↓
┌─────────────────────────────────────────────────────┐
│               MCP Server                            │
│      (你写的 obsidian-mcp-server.js)               │
│                                                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │  Tools   │  │Resources │  │ Prompts  │        │
│  └──────────┘  └──────────┘  └──────────┘        │
└──────────────────────┬──────────────────────────────┘
                      │
                      ↓
               本地文件 / 数据库 / API
```

## 三种能力

| 能力 | 说明 | 类比 |
|------|------|------|
| **Tools** | AI 可调用的函数 | `calculate`、`obsidian_search` |
| **Resources** | AI 可读取的数据 | 文件内容、数据库记录 |
| **Prompts** | 预定义的提示模板 | 固定格式的系统提示 |

## 传输方式

MCP Server 和 Client 之间有多种通信方式：

| 方式 | 描述 | 使用场景 |
|------|------|----------|
| **stdio** | 通过标准输入/输出通信 | 本地子进程（最常见） |
| **SSE** | Server-Sent Events over HTTP | 需要穿透防火墙 |
| **Streamable HTTP** | HTTP 长连接 | 现代主流方式 |

你的 Codex 用的是 **stdio** 方式——Server 是一个子进程，AI Client 通过管道与它通信。
